# Respostas — Correção Integral End-to-End do Relay P2P, OCR Mobile e Autofill CCHA

<!-- tearform v2 -->
## Fase 0 — Reconhecimento Automático Prévio

- O teste realizado no celular e na extensão falhou devido a 5 causas raízes interligadas:
  1. No `scanner.js` do PWA mobile, após o OCR processar a imagem, a execução retornava (`return;`) sem chamar `sendToExtension`, fazendo com que apenas o fallback com dados mockados fixos ("Dr. Lucas Silva / R$ 14.850,00") fosse transmitido.
  2. A pasta `extension/core/` continha uma cópia desatualizada dos arquivos do `core/`, fazendo a extensão executar versões antigas dos parsers e regexes.
  3. No `document-parser.js`, a função `extractTextFromPdfContent` retornava o conteúdo binário bruto do arquivo quando o PDF possuía streams compactadas (`FlateDecode`), impedindo o fallback de OCR e poluindo o extrator de campos com bytes ilegíveis.
  4. Fotos de câmeras modernas de smartphones (10MB+) eram enviadas em base64 bruto sem redimensionamento, sobrecarregando a requisição HTTP local.
  5. Incompatibilidade de máscaras no `content.js` para o portal CCHA (formatos `YYYY-MM-DD` para `input[type="date"]` e normalização monetária para Reactive Forms).

---

## Premissas Permanentes

> Zero Retenção: Todas as fotos, dados e transmissões P2P operam exclusivamente em memória efêmera (RAM), com destruição automática pós-consumo.
> Sincronização Atômica: O motor `extension/core/` deve ser um espelho exato e automatizado de `core/`.
> Resiliência Mobile: O celular deve redimensionar imagens em canvas client-side antes do envio e garantir a transmissão para a extensão no computador.
> Autofill Universal: O content script deve respeitar o tipo de entrada (data, texto mascarado, valor monetário) e o ciclo de vida reativo do Angular CCHA.

---

## B1. Perguntas e Respostas do Requisito

**Q1.** Como deve funcionar o fluxo do scanner mobile ao tirar a foto?
**R:** A foto é capturada, redimensionada via HTML5 Canvas (resolução máxima de 1600px com preservação de proporção) para gerar um JPEG leve de ~200-300KB, enviada para OCR e, com os dados extraídos, transmitida obrigatoriamente para a extensão via `/api/relay/upload` com a sessão correspondente.

**Q2.** Como deve se comportar o extrator de PDF quando não houver texto ASCII legível?
**R:** Se o PDF tiver streams comprimidas ou for escaneado e nenhum fragmento de texto for extraído pelos operadores, deve retornar string vazia `''`, permitindo que o `sidepanel.js` detecte a ausência de texto digital e acione o fallback de OCR óptico.

**Q3.** Como evitar descompasso entre `core/` e `extension/core/`?
**R:** Sincronizar todos os arquivos de `core/` para `extension/core/` e incluir script `npm run sync-core` no `package.json` para validação em CI e build.

**Q4.** Quais ajustes de injeção o `content.js` deve realizar no portal CCHA?
**R:** Identificar se o input alvo é `type="date"` (injetando `YYYY-MM-DD`) ou texto com máscara (injetando `DD/MM/AAAA`), limpar prefixo `R$` quando o campo possui máscara reativa, e despachar eventos completos (`InputEvent`, `change`, `blur`).
