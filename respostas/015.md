# Respostas — S2-T3 e S2-T4: Injetor de Eventos Reativos e Mapeador Semântico de Selects

<!-- tearform v2 -->
## Fase 0 — Diagnóstico & Metas Técnicas

- Em formulários modernos de portais como CCHA, SISU, Conab e sistemas judiciais construídos com Angular (Reactive Forms, Angular Material), React ou Vue, atribuir `input.value = val` diretamente frequentemente falha: quando o usuário clica fora (blur) ou clica no botão de submissão, os valores voltam a ficar vazios porque os interceptores de reatividade do framework não detectaram a mudança via setters nativos.
- Além disso, para campos de seleção (`<select>`), as opções dos portais utilizam nomenclaturas ligeiramente diferentes (ex: "Nota Fiscal de Serviços Eletrônica", "NFS-e", "DANFE Simplificada", "Recibo de Prestação de Serviços"). Sem um casamento semântico determinístico com fallback seguro para "Outros", a seleção quebra ou seleciona opções incorretas.
- A meta desta tarefa é consolidar a função `setInputValueWithEvents` usando prototype property descriptor setters, despachar `InputEvent` com `inputType: 'insertText'` e eventos com `composed: true`, e aprimorar o mapeador semântico de selects O(N) com tolerância fonética/diacrítica e fallback seguro.

---

## Premissas Permanentes

> **Universalidade de Frameworks:** O injetor deve funcionar de forma transparente em Angular (Material / ng-select), React, Vue e HTML tradicional sem necessidade de bibliotecas externas.  
> **Comportamento Idêntico ao Usuário Humano:** A cadeia de eventos disparada (`input`, `InputEvent:insertText`, `change`, `blur`) deve reproduzir com fidelidade a digitação real.  
> **Fallback Seguro para Selects:** Quando uma nota contiver uma categoria não idêntica, o mapeador deve buscar a melhor correspondência semântica e, se não encontrar, selecionar com segurança a opção de fallback "Outros".

## B1. Perguntas e Respostas do Requisito

**Q1.** Como implementar a função `setInputValueWithEvents` em `extension/content.js`?  
**R:** Será implementada extraindo o property descriptor de `HTMLInputElement.prototype` ou `HTMLTextAreaElement.prototype` via `Object.getOwnPropertyDescriptor(proto, 'value').set.call(input, val)`, garantindo que os wrappers do React e Reactive Forms do Angular registrem a mutação interna. Em seguida, disparamos a sequência reativa: `Event('input', { bubbles: true, cancelable: true, composed: true })`, `InputEvent('input', { bubbles: true, cancelable: true, composed: true, inputType: 'insertText', data: val })`, `Event('change', { bubbles: true, cancelable: true, composed: true })` e `Event('blur', { bubbles: true, cancelable: true, composed: true })`.

**Q2.** Como garantir que o label flutuante do Angular Material se ajuste automaticamente?  
**R:** Se o input estiver contido em `<mat-form-field>`, as classes CSS `mat-form-field-should-float` e `mat-focused` continuam sendo adicionadas defensivamente.

**Q3.** Como funciona o algoritmo de correspondência semântica de `<select>` (S2-T4)?  
**R:** O algoritmo `matchSemanticSelectOption` opera em 3 estágios O(N):
1. **Match Direto:** Compara texto e valor normalizados (sem acentos e em minúsculas).
2. **Mapeamento de Grupos Fiscais:** Grupos pré-calibrados mapeiam variações (ex: "DANFE", "NFC-e", "Nota Fiscal", "Cupom" -> "nota_fiscal").
3. **Fallback Seguro para Outros:** Se nenhuma opção do grupo for encontrada, busca opções como "outros", "outro" ou "diversos" no `<select>` para evitar campos em branco.

**Q4.** Como esses comportamentos serão testados via TDD?  
**R:** A suíte em `tests/extension/content.test.js` receberá cenários com inputs do React/Angular simulando setters no prototype, verificação das flags `composed: true` nos eventos, e cenários de selects variados testando mapeamento semântico de DANFE/NFC-e e fallback para Outros.
